# Licence register: CrewFlow (`crewflow1/web`)

Workstream: Licence / Copyright / SBOM. Baseline: `origin/main` @ `8cec66a7`, 2026-11-13; **refreshed 2026-11-16 against `origin/main` @ `d24295e`** (package-lock.json unchanged between the two, so totals are identical; node_modules was re-installed with `npm ci --ignore-scripts`, so more packages were read from disk).
Evidence labels as per AGENT-RULES §5. Nothing in this file is legal advice; it is an engineering licence audit for the founder and counsel.

## 1. Verdict in one paragraph

Across all **1,126** entries in `package-lock.json` there is **no strong-copyleft (GPL/AGPL/SSPL), no non-commercial, no source-available (BUSL/Elastic/Commons-Clause/PolyForm/CC-NC) and no "SEE LICENSE IN" package**. The production graph (759 packages) is 745 permissive + 14 weak-copyleft, and all 14 are the LGPL-3.0 `libvips` / `sharp` platform binaries used server-side only by Next image optimisation. Three packages are dual-licensed and CrewFlow uses the permissive option of each. One package (`png-js`) has no licence field but ships an MIT text. The real, actionable gaps are about **attribution and housekeeping**, not about a licence that forbids commercial SaaS use: (a) no THIRD-PARTY-NOTICES is published although client bundles carrying MIT/ISC/Apache code are distributed to browsers; (b) CrewFlow itself has no LICENSE/`"license"` statement; (c) the marketing typefaces (Clash Display, Satoshi) are under the ITF Free Font License, which requires credit and whose primary terms text could not be retrieved in this session. **VERIFIED** by `scripts/compliance/licence-inventory.mjs` (output `licence-inventory.csv/json`).

* The inventory script reads, per package, (1) `package.json` `license`/`licenses`, (2) every `LICENSE*/COPYING*/NOTICE*` file, fingerprinted against known licence text (whitespace-normalised), (3) the `license` field npm recorded in the lockfile; and flags any disagreement. Source of the on-disk read: worktree 550 prod packages, version-matched fallback tree (`~/Code/web/node_modules`) 102, **lock-only 107** (all platform-specific optional binaries, e.g. `@next/swc-linux-x64-gnu`, not installable on a macOS machine; their licence comes from the lockfile only). Per-row `source` column. **VERIFIED**.
* Declared-vs-lock agreement: 0 mismatches. Text-vs-declared differences: 6 (section 5).
* "Client-bundle" is a **static heuristic**, not a bundle analysis: it follows imports from every `"use client"` file and the Sentry client entry, then expands through lockfile `dependencies`. It over-approximates (barrels such as `lib/comms/index.ts` make `twilio`, `stripe`, `openai`, `@anthropic-ai/sdk`, `resend` look client-reachable although `server-only`/build rules should prevent that). Read `client_bundle = direct-client-import | client-transitive` as "assume it ships to browsers", and `server/build-only` as "not found in the client graph". An authoritative answer needs a `next build` bundle analysis (not run: heavy, and the partial `node_modules` here would make it unrepresentative). **IMPLEMENTED-UNTESTED** as a precise statement; fine as a conservative bound.

* Files: `app/_marketing/fonts/{ClashDisplay-Medium,Semibold,Bold,Satoshi-Regular,Medium,Bold}.woff2`, loaded with `next/font/local` (self-hosted; no Fontshare request at runtime, **VERIFIED** `app/_marketing/fonts.ts` + CSP `font-src 'self' data:`).
* Embedded metadata (read with fontTools, **VERIFIED**): copyright "Indian Type Foundry", licence URL `https://fontshare.com/terms`, name-table note: "You agree to identify the ITF fonts by name and credit the ITF's ownership of the trademarks and copyrights in any design or production credits."; `fsType = 0` (installable embedding).
* The repo comment says both are free for commercial use with self-hosting. Secondary sources (ITF announcement, licence summaries) agree on free commercial use and self-hosted webfont use, and on **no redistribution of the font files**. I could **not** retrieve the primary terms text (fontshare.com is a JS app; fetch returned no licence text), so the exact redistribution wording is **NEEDS-FOUNDER** (keep the licence PDF/receipt from the Fontshare download kit). Practical consequences: (1) serving WOFF2 to site visitors via your own origin is the permitted web use; (2) keep the `crewflow1/web` repository **private**: committing the font binaries to a public repo would be redistribution; (3) render a credit (e.g. in the notices page: already included in the generated file).

## 8. Apache-2.0 NOTICE and attribution

* 82 production packages are Apache-2.0 (58 in the heuristic client closure, notably `pdfjs-dist`, `posthog-js`, `openai` (heuristic only), `@opentelemetry/*`, `@swc/helpers`, `import-in-the-middle`). Apache §4 requires: give recipients a copy of the licence; keep copyright/patent/attribution notices; reproduce the contents of any `NOTICE` file; mark modified files (none modified).
* NOTICE files in the production graph: only `import-in-the-middle` (Node.js contributors + Datadog attribution), reproduced in THIRD-PARTY-NOTICES. (`playwright*` ship NOTICE but are dev-optional and not shipped.)
* App currently satisfies this only for the pdf.js worker (header retained). Everything else depends on L-1.

## 9. Recommendation summary

1. Publish THIRD-PARTY-NOTICES (L-1), regenerate on dependency change (`generate-notices.mjs`; CI wiring is a suggestion: `node scripts/compliance/licence-inventory.mjs` could fail the build on any new non-permissive production licence, using the `class` column).
2. Add copyright/licence statement (L-2) after founder names the owner.
3. Remove unused `react-email` and `@react-email/components` (V-02) which also removes their nested copies.
4. Keep `sharp` dynamic; revisit LGPL only if CrewFlow ever ships an installable/on-prem artefact.
5. Add a CI guard so no GPL/AGPL/SSPL/NC/BUSL/unknown licence can enter the production graph silently (proposed, not implemented).
