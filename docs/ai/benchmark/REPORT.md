## 1. Question this answers

CrewFlow's AI today is fully hosted: **Anthropic Claude** for text (cheap→Haiku
4.5, mid→Sonnet 5, high→Opus 5, per `lib/ai/governor/registry.ts`), **OpenAI
`text-embedding-3-small`** (1536-d) for embeddings (`lib/ai/embeddings/openai.ts`),
and **OpenAI Whisper** for transcription (`lib/ai/transcription/openai.ts`).

Could small, locally-run, commercially-licensed models **replace** or **cheaply
fall back for** any of these workloads — and what would it actually cost to run
the viable ones in production (which is *not* a laptop)?

## 2. Verdict (TL;DR)

- **Embeddings and speech-to-text are the clear wins.** Local `bge-m3` retrieves
  as well as we need (first relevant doc ranked #1 on every query) and
  `whisper.cpp base.en` transcribes at ~7% WER and **28x real-time** on CPU.
  Both are near-zero marginal cost and worth piloting off the OpenAI path.
- **Interactive text generation: keep hosted (Claude), add local as an optional
  cheap fallback for the latency-tolerant, non-critical workloads.** The best
  commercially-clean local model (**Phi-4-mini**, MIT) is genuinely good on
  summaries/drafts/extraction but a 3-4B model on a laptop is not production
  infra, and the quality floor on harder tasks is not Claude's.
- **One model to avoid as-is: `qwen3:4b`.** Its default "thinking" mode burns the
  whole output budget reasoning and often returns **nothing** on strict/short
  tasks (24-35s to first answer token; empty JSON). Usable only with thinking
  disabled — not benchmarked in that mode here.
- **One licence flag: `qwen2.5:3b` scored best overall but is NOT Apache/MIT**
  (Qwen Research License). Do not ship it to production without legal review.

| Repeats | 1 per item (latency is indicative, not a p50/p99 study) |
| Hosted baseline | **Not called.** Claude/OpenAI numbers are reference only — this is **not a live A/B.** |

**Quality score is a deterministic heuristic, not a human judgment and not an LLM
judge.** It blends keyword/fact coverage (0.55), output hygiene — no refusals or
tell-tale failure strings (0.25), and length adherence (0.20); JSON tasks score
schema-validity (0.5) + field accuracy vs. gold (0.5). This is reproducible and
dependency-free, but it rewards "mentions the right things in the right shape",
which is a proxy for quality, not quality itself. Treat the numbers as a triage
signal; anything near a go/no-go boundary needs a human read. Scoring code:
`scripts/benchmark/lib/score.mjs`.

"**Fallback-worthy failure**" = the output refused, was empty, failed schema, or
missed most key facts — i.e. a request that *should* have escalated to a hosted
model. It is the most decision-relevant column.

## 7. Embeddings vs. the OpenAI path (conceptual, not a live A/B)

We did **not** call OpenAI. Comparison is on dimensions, public MTEB reputation,
and local latency only:

| | OpenAI text-embedding-3-small (prod) | bge-m3 (local candidate) |
|---|---|---|
| Dimensions | 1536 | 1024 (dense mode) |
| Licence | proprietary API | **MIT** |
| MTEB reputation | strong, widely-used general retriever | strong multilingual retriever; competitive on English |
| Retrieval on our corpus | not measured (hosted) | **MRR 1.00, first-relevant rank 1.00, recall@3 1.00** |
| Marginal cost | **$0.02 / 1M tokens** + vendor dependency | **~$0** on existing compute |
| Operational | external call per memory write; subject to the Supabase 30-Oct Data-API/vendor surface | self-hosted, no egress, no key |

**Recommendation:** pilot `bge-m3` behind the existing
`lib/ai/embeddings/` provider seam (the architecture already assumes the vendor
is swappable — `embeddings/types.ts` names this explicitly). Changing dimensions
(1536->1024) means a **re-embedding migration** and a new embedding `version`
tuple, so it's a deliberate backfill, not a config flip. The quality case is
sound; the win is cost + removing a vendor, not a quality jump.

## 8. Production-hosting reality & cost

**Moe's M3 Mac is not production infrastructure.** It is single-user, has no SLA,
no uptime guarantee, no concurrency headroom, and is shared with dev work. Every
"PASS FOR LOCAL" above means *the model is good enough*, **not** *run it on the
laptop*. To actually serve these you need one of:

### 8.1 What each hosted baseline costs today (reference)

- Claude **Haiku 4.5** $1 / $5 per MTok (in/out); **Sonnet 5** $2 / $10; **Opus 5**
  $5 / $25. (Current-gen **Haiku 5.5** is **$0.10 / $0.50** — ~10x cheaper than the
  4.5 the governor is pinned to; migrating the cheap tier is likely a bigger, zero-ops
  win than self-hosting text at CrewFlow's scale.)
- OpenAI **text-embedding-3-small** ~$0.02 / MTok. OpenAI **Whisper** ~$0.006 / min.
  (Public rates; confirm current.)

### 8.2 What self-hosting the PASS-FOR-LOCAL models would cost

| Option | Rough cost | Fits which workloads | Notes |
|---|---|---|---|
| **Existing CPU box** (a container alongside the app, 2-4 vCPU / 8 GB) | **~$0 marginal** | embeddings (bge-m3), STT (whisper base.en) | Both are tiny, batchable, and infrequent. **Genuinely near-zero marginal cost.** |
| **Always-on small CPU VM** (4 vCPU / 16 GB) | **~$50-120 / mo** | async/batch text (digests, release notes, memory summaries) | CPU text gen is slow (single-digit-low-20s tok/s) and single-concurrency; fine when no user waits. |
| **Always-on small GPU** (cloud L4/T4-class) | **~$350-750 / mo** | interactive local text with modest concurrency | Fixed monthly cost whether or not it's used; only wins at sustained volume. |
| **Serverless GPU** (per-second, e.g. Modal/RunPod-style) | pay-per-use + cold starts | bursty text | Cold starts hurt interactive latency; good for spiky batch. |

### 8.3 Which workloads are genuinely near-zero marginal cost vs. need paid hosting

- **Near-zero (strong self-host case):** **embeddings** and **STT**. Tiny compute,
  batchable, infrequent, CPU-only, MIT-licensed. These are the two to pilot — they
  remove a vendor and a per-call cost at essentially no new spend.
- **Needs paid hosting to be worth it:** **interactive text**. A 3-4B model needs a
  CPU VM (slow, async-only) or a GPU (fixed monthly). Against Haiku 5.5 at
  $0.10/$0.50 per MTok with zero idle cost and full scale-to-zero, self-hosting
  interactive text **does not pay off** at CrewFlow's current scale. Keep Claude
  for interactive/critical text; local text earns its place only as (a) an offline/
  degraded-mode fallback, or (b) an async batch worker on a cheap CPU box for
  latency-tolerant jobs.

## 9. Key findings worth remembering

1. **`qwen3:4b` is a trap in default mode.** Thinking consumes the output budget ->
   24-35s to first answer token and **empty** outputs on invoice/release-notes
   (quality 0.00, 100% fallback-worthy). Only consider it with thinking disabled
   (`/no_think` / `think:false`), re-benchmarked.
2. **JSON/structured output separates the models.** phi4-mini and qwen2.5 hit
   **100%** schema compliance + 100% field accuracy on invoice extraction; phi3.5
   managed only **20%** schema (quality 0.38). If you self-host for extraction,
   model choice is load-bearing — test it.
3. **The best overall scorer is licence-blocked.** `qwen2.5:3b` (0.9-1.0 across the
   board, 0% fallback everywhere) is under the **Qwen Research License, not
   Apache**. **Phi-4-mini (MIT)** is the right default for any commercial pilot.
4. **The heuristic flatters reasoning tasks.** 1.00 on design_review /
   hq_prospect_analysis reflects *structure*, not Opus-grade judgment — those stay
   hosted-fallback.
5. **Embeddings + STT are the real, bankable wins** — quality is there, licences
   are clean (MIT), and the marginal cost is ~zero on existing compute.

## 10. Recommended next steps (all gated, none autonomous)

1. Pilot **bge-m3** behind the `lib/ai/embeddings/` seam on a scratch corpus;
   measure retrieval on *real* (not synthetic) memory data before any backfill.
2. Pilot **whisper.cpp base.en** for voice-note transcription on a CPU worker;
   compare WER against OpenAI Whisper on a small real sample.
3. For text, **first evaluate migrating the cheap tier to Haiku 5.5** (zero-ops,
   ~10x cheaper) before investing in self-hosted text at all.
4. If pursuing local text fallback, standardise on **Phi-4-mini (MIT)** and
   re-benchmark **qwen3:4b with thinking disabled**.
5. None of this activates anything: providers stay dark; any switch is a
   deliberate, human-approved config + (for embeddings) a migration.
