# CrewFlow Local AI Benchmark Harness

**RESEARCH ONLY. NOT FOR MERGE. NO PRODUCTION CONNECTION. NO REAL DATA.**

This harness measures whether small, locally-run, commercially-licensed models
(via [Ollama](https://ollama.com) + whisper.cpp) are good enough to serve — or
to cheaply fall back for — CrewFlow's AI workloads, versus the production hosted
stack (Anthropic Claude for text, OpenAI `text-embedding-3-small` for
embeddings, OpenAI Whisper for STT).

It does **not** call any hosted API and does **not** touch CrewFlow production,
Supabase, or any real customer data. Every fixture is synthetic and anonymised.

## What it measures

Per `(model × workload)`: output quality (deterministic rubric), JSON/schema
compliance rate (for structured tasks), latency (time-to-first-token + total),
tokens/sec, loaded-model memory (RSS/size as reported by Ollama), and a
"fallback-worthy failure" flag (refusal / empty / schema-fail / missed key
facts → would have needed a hosted model).

For embeddings: retrieval quality (precision@k, recall@k, MRR, mean rank of
first relevant doc) on a synthetic corpus, plus dimensions and local latency,
compared **conceptually** (not via a live A/B) against the OpenAI path.

For STT: word error rate (WER) and real-time factor on synthetic voice notes
generated by macOS `say` (no real voice).

## Layout

```
scripts/benchmark/
  run.mjs                 # main text + embedding runner (Node, no deps)
  run-stt.mjs             # STT runner (drives whisper.cpp)
  gen-audio.sh            # generates synthetic audio via macOS `say`
  config.mjs              # model registry + licences + production baseline map
  lib/ollama.mjs          # minimal Ollama client (streaming, timed)
  lib/score.mjs           # rubric + JSON-schema validator + retrieval metrics
  fixtures/*.json         # 10 text/JSON workloads + embedding corpus + STT refs
  schemas/invoice.schema.json
  results/snapshot-*.json # committed results snapshot (latest.json is gitignored)
```

## Running

```bash
export PATH="/opt/homebrew/bin:$PATH"          # node/npm/brew on this Mac
brew install ollama && ollama serve &          # once
ollama pull phi4-mini qwen3:4b phi3.5 nomic-embed-text bge-m3

export OLLAMA_HOST=127.0.0.1:11434
node scripts/benchmark/run.mjs                 # full run → results/latest.json
node scripts/benchmark/run.mjs --models phi4-mini --workloads 03-invoice-extraction
node scripts/benchmark/run.mjs --dry-run       # validate fixtures without Ollama

# STT (optional, needs whisper.cpp):
bash scripts/benchmark/gen-audio.sh
node scripts/benchmark/run-stt.mjs
```

Model weights, audio, the venv and raw `latest.json` are gitignored. Re-run to
regenerate; commit a `results/snapshot-*.json` to preserve a point-in-time run.

## Methodology honesty

The quality score is a **deterministic heuristic** (keyword coverage + format +
hygiene), not an LLM judge — so runs are reproducible and dependency-free, but
the absolute numbers are a proxy, not a human quality verdict. See
`docs/ai/benchmark/REPORT.md` for the full methodology, caveats, and the
production-hosting cost reality.
